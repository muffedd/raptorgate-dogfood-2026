# Portable judge participation certificate (T4 slice)

This route produces a signed JSON participation claim, not a PDF diploma or proof of judging quality. The claim includes an event slug, judge slug, eligible review count and issuance time; no individual scores or comments are included. Publishing the judge slug and count is an organizer privacy choice.

Set `CERTIFICATE_PRIVATE_KEY_PEM` to a separate Ed25519 private key in the server environment. The value may have literal `\n` escapes. Generate it outside the repository, keep it private and publish its corresponding raw public key fingerprint through a trusted event channel. The checked-in Django/demo keys cannot sign certificates. `cryptography` is a pinned dependency. The server stores only the signed payload, public key and signature, not the private key.

After the active event's voting closes and results are published, an authenticated organizer may `POST /organizer/certificates/issue` with `judge=<slug>` and a CSRF token. The judge must have at least one eligible canonical project score. The first issuance freezes the review count and time; repeated calls return the original certificate. `GET /certificates/<id>.json` downloads the signed document once results are public. If the stored payload or signature is altered, download returns 409. The document can be verified independently with Ed25519 over UTF-8 JSON serialized with sorted keys, separators `(',', ':')`, and `ensure_ascii=False`, using the base64url public key and signature in the document.

**Trust limit:** A valid self-contained signature only proves consistency with the document's embedded public key. It does not identify the event organizer unless the verifier compares that key against a fingerprint published separately over a trusted channel. The organizer controls the database and can issue a claim with its private key; this is a signed statement of recorded participation, not independent proof that reviews happened. Key rotation leaves old certificates valid when their old public key is trusted, but separate event key publication and revocation policy are not built. There is no PDF design, judge-facing distribution UI, or bulk issue. Do not claim full T4 from this slice.

A local, standalone verification command is `python verify.py certificate.json --trusted-public-key <base64url raw public key from a trusted organizer channel>`; it requires only `cryptography`. Without the trusted key option it reports only internal signature validity, not the identity of the signer. The public `/verify` page checks a pasted certificate against this site's published issuance as well as its signature. It also checks published receipt tokens and HMAC participation record IDs with distinctly weaker, server-bound meanings; none are a blanket proof of fairness.
