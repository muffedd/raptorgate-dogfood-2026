# Offline deployment bundle (proposed, not yet verified)

The standard `docker-compose.yml` needs network access on a cold machine because it pulls Python/PostgreSQL images and installs Python packages at build time. These scripts prepare a platform-specific image archive on an online Docker host, then load it and start Compose without pulling or building on the offline machine. This is a distribution plan, **not a passed fresh-machine rehearsal**. The current repo does not ship the image archives.

0. Require Docker Engine/Desktop and Compose on the destination before disconnecting the network. The scripts cannot install Docker offline. The current bundle is not a proven judge-ready artifact.
1. On an online Docker host, run `packaging/build-offline-bundle.sh`. It builds Linux amd64 and arm64 portal images and saves each architecture's portal/PostgreSQL images to `dist/raptorgate-$arch.tar`, with a SHA-256 checksum. This requires `docker buildx`, Docker image storage compatible with multi-platform pull, enough disk, and successful dependency installation. Pin image digests before treating this as a reproducible release; the current tags alone can move. Sign the checksum manifest in the release process if the publisher has a managed signing key; a checksum by itself detects corruption but not malicious replacement.
2. Transfer this checkout and the corresponding `dist/` archive to the target laptop. Install Docker with Compose in advance (Linux Docker Engine, macOS/Windows Docker Desktop), then disconnect network access.
3. Run `packaging/run-offline.sh` on macOS/Linux. It verifies archive SHA-256, loads matching Linux architecture images, and runs Compose with `--no-build --pull never`. Windows users can run `packaging/run-offline.ps1` in PowerShell; this script has not yet been tested on Windows.
4. Prove with empty Docker image store + empty volumes, network off: the portal loads at `127.0.0.1:8080/projects`, CSS loads, 41 fixture project rows / 126 scores are seeded, and `python3 run.py .dogfood.toml` prints seven literal PASS lines. Capture OS, architecture, Docker/Compose versions, image digests, archive SHA, startup log, curl and checker output. Repeat on amd64 and arm64; macOS/Windows still need their own test.

Local demo credentials and fixed session headers in the repository are not safe on a public server. Compose binds to loopback. A blank offline machine without a previously transferred image archive cannot run a Python/PostgreSQL container from source alone. Do not present `docker compose up` on a warmed development machine as proof of this stricter case.
